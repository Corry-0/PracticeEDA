# 工程师自定义元件与网表导出

## 创建与复用

1. 打开“项目 → 新建自定义元件”，填写元件名称。
2. 输入和输出分开填写，每行采用 `名称:位宽`，例如输入 `DATA:8`、`CLK:1`，输出 `Q:8`。接口名称不可重复，位宽为 1–32；输入或输出可单独留空，总接口数量为 1–64。
3. 创建后打开元件定义画布，自动放置命名接口。添加门、总线、寄存器、存储器或其他自定义元件并连线，实现所需功能。新建操作只生成接口，内部逻辑由工程师设计。
4. 在左上角切回 `main` 或其他调用电路，从左侧“自定义元件 / 子电路”库选择元件并放置。搜索框支持元件名称；双击实例进入定义。
5. 在属性面板修改接口名称和位宽。名称变化保留原连接，因为连接使用稳定的接口 ID；位宽变更后应查看诊断并同步调整外部总线。
6. 在定义画布使用“项目 → 保存当前电路为元件”，生成 `.component.json`。已有电路也可以直接保存为元件，只需至少包含一个 Input 或 Output。`examples/half-adder.component.json` 可直接试用。
7. 其他工程通过“项目 → 导入自定义元件”读入。导入后进入放置模式，单击画布创建实例，Esc 取消放置；定义仍保留在库内。导入与放置分别支持撤销重做。

自定义元件与子电路使用同一个仿真模型，支持组合逻辑与时序逻辑。每个实例拥有独立的寄存器/RAM 状态。编辑定义会影响当前工程内的所有实例，并按既有结构编辑行为复位仿真。元件文件是快照，修改原工程不会自动修改已经导入其他工程的定义。

## 元件文件

外层标识为 `format: "PracticeEDA.component"`、`version: 1`，`project` 保存完整的数字工程结构，`project.main` 指定该元件的根定义。文件只包含根定义及其递归依赖，不包含无关电路。

导入先校验，再在候选工程上处理名称和 ID。已有定义不会覆盖，重名使用 `_import1`、`_import2` 等后缀；对象 ID、导线两端及嵌套实例端口 ID 一并重映射。未知版本、非法位宽、无效端点、递归引用、超过工程容量等错误会拒绝导入，原工程保持不变。工程数量上限仍为 128，文件上限仍为 32 MB。工程保存格式继续使用原有 `.logic.json` 第 1 版，旧示例可直接读取。

## 导出网表

打开“文件 → 导出网表”，选择所需格式。导出范围是**当前打开的电路及其全部嵌套实例**；若需整个主电路，先切回 `main`。与当前电路无关的定义不会加入网表。

导出采用仿真器编译出的连接网络，因而同名节点连接、显式分支、层次接口连接和实例隔离遵循现有仿真语义。画面上的导线交叉不会凭空变成连接。导出不执行事件、不切换时钟、不改动输入值、寄存器、RAM、事件队列或工程历史。

### KiCad S-expression `.net`

采用 `(export (version "D") ...)` 形式，包含 `design`、`components`、`nets`。连接结构参考 [KiCad 官方网表文档](https://docs.kicad.org/6.0/en/eeschema/eeschema.html#netlist-formats)。

- 展开到基本逻辑元件，并以 `U1`、`U2` 等唯一引用标识元件；`InstancePath` 字段记录原层次实例路径，`Label` 保留元件显示名。
- 保留 `Width`、`InitialValue` 和 `MemoryData` 字段，后两者是工程初值，**不是正在运行的状态快照**。
- 总线按最低位从 0 开始展开，如 `Y[0]`–`Y[7]`；网络名为 `N1[0]` 等。单比特引脚保持 `Y`、`CLK` 等原名。
- 悬空引脚仍有单独网络，未连接输出不会被默默删除。文字标签不是电气元件。

这是逻辑连接交换文件：元件仍为虚拟 AND、Register、RAM 等，不包含实体芯片引脚号、PCB 封装或模拟器件模型；不是 SPICE 或 Verilog 仿真程序，不能直接作为可生产 PCB 的网表。已验证语法和连接对应关系，未用外部 KiCad 完成 PCB 导入验收。

### 完整数字网表 `.net.json`

标识为 `format: "PracticeEDA.netlist"`、`version: 1`。

| 字段 | 含义 |
| --- | --- |
| `project` / `circuit` | 工程名称 / 当前导出根电路 |
| `components[].ref` / `path` | 网表唯一引用 / 原始实例层次路径 |
| `kind` / `label` / `width` | 元件类型 / 标签 / 数据位宽 |
| `value` / `data` | 工程初值 / 存储器初始化数组 |
| `components[].pins[]` | 引脚 ID、方向、位宽和所属网络编号 |
| `nets[].id` / `name` / `width` | 网络编号、稳定生成名称和总线位宽 |
| `nets[].aliases[]` | 合并到此网络的原始元件端口、层次接口、节点和导线端点标识 |
| `nets[].labels[]` | 用户网络标签及其所属实例路径 |
| `nets[].pins[]` | 网络连接的基本元件引用和引脚 ID |

网络中所有已知引脚位宽必须一致，否则两种格式都会拒绝导出并提示修复。驱动冲突和悬空等问题仍显示在原诊断面板中，网表忠实记录连接，不将当前 E/X/Z 当成硬连线常量。相同工程多次导出内容确定，可用于版本比较。两种网表均为导出用途，重新编辑请保留 `.logic.json`。
