# EDC / ERC 电气规则功能完整性自查

日期：2026-10-22。对象：当前工作区 Release 核心库、桌面程序与现有回归；包含本次会话此前完成的元件、工具栏和选择交互修改。

后续界面调整说明：诊断已迁为画布颜色、避让元件的外围警示图标和按需列表，聚合气泡已移除；无问题时改为“当前检查范围内未发现问题”，不再显示笼统的“检查通过”。下文保留审计时点的界面观察与证据，规则层缺口尚未补齐。

## 结论

**按用户列出的完整电气规则要求，功能不完整。当前实现覆盖部分数字电路结构校验和运行态连接诊断，缺少独立于当前信号值的静态 ERC 规则层。**

本次新增独立审计程序和 26 组可打开的最小工程，未修改产品代码或补齐缺失规则。全部用例完成观察，结构上有意非法的 4 个工程被拒绝；审计程序执行成功不表示这些工程通过完整 ERC。

原有 Release CTest 为 **11/11 通过**，GUI 五组回归标志通过。这些结果证明已有功能没有在本次检查中失败，不能证明本报告列出的缺失规则已实现。

## 逐项核对

| 用户要求 | 当前状态 | 核对结果 |
| --- | --- | --- |
| 悬空必选输入 | 已有基础检查 | 接收端为 Z 时报警；输入连接到无驱动网络也会报警。当前诊断依赖运行态，与禁用三态输出等正常高阻情形使用同一类提示。 |
| 单端网络、悬空输出、导线自由端 | 缺失专项规则 | 未使用输出、输出连到自由节点、只有节点和导线的网络均可无诊断。没有“不连接”标记及对应规则策略。 |
| 未驱动引脚 | 部分支持 | 普通接收端可由 Z 检出；仅包含 CLR/CLEAR 的网络被整体豁免，已经接线但没有驱动的 CLR 也会漏检。 |
| 引脚类型冲突 | 部分支持 | 端口仅有输入/输出布尔属性与位宽，没有完整电气类型及兼容矩阵。输入对输入会因无驱动间接报警，输出类型冲突没有独立静态判定。 |
| 输出短路 | 部分支持，有实测漏检 | 不同电平的强输出相连会产生 E；同电平普通输出相连无诊断，改变输入后会报警，再变回同电平后报警消失，连接拓扑始终未改变。 |
| 电源网络驱动 | 缺失完整规则 | Power/Ground 是数字信号源；没有 power input/output 类型、供电域、未供电引脚或电源驱动标记等可供检查的信息。普通逻辑输出与同电平 Power 直连可以无诊断。 |
| 电源与地短路 | 部分支持 | 实际 Power 与 Ground 直接相连可检出通用驱动冲突；名为 VCC/GND 的普通标签不具有电源类型语义，不能据此识别供电域混接。 |
| 网络命名冲突 | 缺失命名规则 | 本实例内完全同名节点会自动连接，跨实例保留作用域；一个网络上的不同标签作为别名被接受。没有名称优先级、冲突策略或别名授权检查。多个别名未必就是错误，完整规则需要明确策略。 |
| 相似标签 | 缺失 | 两个已正常驱动的独立网络分别使用 CLK/clk，未出现相似性提示。未实现大小写、空白、近似拼写等专项筛查。 |
| 悬浮标签 | 缺失 | 只有孤立网络标签、没有任何引脚或同名远端连接时，无诊断。普通文字注释也不具有电气标签语义。 |
| 位号 | 缺失实体位号校验 | 内部对象 ID 唯一性、接口名称重复已有结构校验；它们与实体位号是不同概念。普通器件显示名称可重复，逻辑导出时 U1/U2 等引用由程序临时生成。 |
| 封装 | 缺失通用校验 | 逻辑元件模型没有封装字段，不支持检查未分配封装、封装不存在、符号脚与焊盘映射不一致等。PCB 导出仅支持限定器件的固定教学映射。 |
| 多单元符号完整性 | 缺失 | 没有封装实例、单元编号/总数、共享电源单元等元数据，无法检查缺单元、重复单元或跨单元属性一致性。子电路定义与实例不是实体芯片多单元模型。 |

## 主要发现及复现证据

### 1. 普通输出同电平短接会被放行

用两个 Buffer 的 Y 端共同驱动一个接收端，两侧 A 分别由 Input 驱动：

- 两个输入都是 0：0 条诊断。
- 仅把第二个输入改成 1：5 条对象级诊断，提示“驱动冲突或非法运算 (E)”。
- 再把第二个输入改回 0：恢复 0 条诊断。

连接没有变化，诊断随运行值出现和消失。`resolve()` 在 `src/Digital.cpp:1635` 逐位合并驱动，并在 `src/Digital.cpp:1666` 仅按错误位或 0/1 冲突设置 E；`Simulator::issues()` 没有另行检查普通输出的静态互连。

工程：[equal-push-pull-outputs.logic.json](evidence/equal-push-pull-outputs.logic.json)、[opposite-push-pull-outputs.logic.json](evidence/opposite-push-pull-outputs.logic.json)。同一拓扑的运行态切换记录在 [results.json](evidence/results.json) 的 `sameTopologyDriverStateChanges`。

注意：5 条诊断对应同一网络上的多个对象，不表示 5 个独立短路。将来增加静态规则时也不能简单禁止所有多输出网络，需要区分三态等电气类型。

### 2. 单端网络及悬浮标签无专项诊断

以下最小工程均为 0 条诊断：

- [未使用输出](evidence/unconnected-output.logic.json)。
- [已驱动输出接导线自由端](evidence/dangling-wire-end.logic.json)。
- [只有节点和导线](evidence/wire-without-pins.logic.json)。
- [孤立网络标签](evidence/floating-label.logic.json)。

根因是 `src/Digital.cpp:1898` 的 Z 检查要求网络存在使用者，且不属于可选端子网络；没有引脚数量、自由端度数、输出负载或孤立标签规则。这些连接是否允许应由规则级别及显式不连接标记决定，目前没有相应机制。

### 3. 已接线但无驱动的 CLR 被豁免

[optional-clear-wired-undriven.logic.json](evidence/optional-clear-wired-undriven.logic.json) 中 D、CLK 均已驱动，Q 连接接收端，CLR 接到独立自由节点。CLR 读数为 Z，诊断仍为 0。

`src/Digital.cpp:1141` 仅按端口名称决定 `optionalOnly`，没有区分“可选端子完全未接线”与“已显式接线的无驱动网络”；`src/Digital.cpp:1898` 对后者也不报警。作为对照，[optional-clear-unconnected.logic.json](evidence/optional-clear-unconnected.logic.json) 是目前已有回归允许的未接线 CLR 情形。

### 4. 电源检查范围限于数字信号冲突及教学映射

- [Power/Ground 直接相连](evidence/power-ground-short.logic.json)：产生 3 条通用 E 诊断。
- [Power 与同电平逻辑输出直连](evidence/power-logic-output-tied.logic.json)：0 条诊断。
- [VCC 普通标签由 Ground 驱动](evidence/vcc-label-driven-by-ground.logic.json)：0 条诊断。
- [同一网络带 VCC/GND 两种普通标签](evidence/mixed-power-labels.logic.json)：0 条诊断。

后两个用例说明当前标签没有供电域含义；不能把所有含 VCC/GND 字符串的用户标签直接当成某种固定电源规则。完整校验需要明确的电源类型和网络属性。

`src/PcbExport.cpp:11` 的 `exportPcb()` 会拒绝已有错误，`src/PcbExport.cpp:22` 另有电源轨冲突保护，并为限定器件自动补充电源引脚、封装和去耦。这是导出阶段的限定映射，不能代替对通用原理图的电源 ERC。

### 5. 网络名称只用于连接和别名，不做名称规则校验

[similar-labels.logic.json](evidence/similar-labels.logic.json) 的 CLK/clk 两个独立网络均已正确驱动，无其他悬空问题，仍为 0 条诊断。[different-labels-one-net.logic.json](evidence/different-labels-one-net.logic.json) 上的 NET_A/NET_B 被接受为同一网络的两个别名。

`src/Digital.cpp:1060` 的 `flatten()` 只在当前实例内按完全相同的标签字符串合并网络；没有相似性、拼写或名称优先级校验。

### 6. 位号、封装、多单元信息无法在现模型中表达

`include/Digital.h:19` 的 `Part` 没有实体位号、封装、单元编号/总数等成员。`include/Digital.h:34` 的 `Port` 只有稳定脚名、输入/输出方向、位宽和坐标，没有实体引脚电气类型。

在一个有效工程的元件 JSON 中添加 `reference`、`footprint`、`unit`、`unitCount` 后加载再保存，这四个字段均未保留。该结果反映当前格式不支持这些元数据，不应被描述为已有实体模型的回归问题。原始观察见 [results.json](evidence/results.json) 的 `physicalMetadataSurvivesRoundtrip`。

[duplicate-ordinary-labels.logic.json](evidence/duplicate-ordinary-labels.logic.json) 另证实两个普通器件的显示名称可以同为 U1；这也不能当作实体位号已被校验。

### 7. 检查范围与定位粒度需要明确

- [未实例化定义中的悬空输入](evidence/unused-invalid-electrical-definition.logic.json)：根电路诊断为 0。结构校验会遍历全部定义，仿真连接诊断只覆盖当前仿真根实际展开的实例。
- [同一与门两个输入悬空](evidence/ambiguous-pin-diagnostics.logic.json)：两条诊断的对象和消息相同，没有具体 A/B 脚名。`Issue` 当前仅含 severity/object/message，缺少规则代码、网络 ID 及具体引脚。
- `src/DigitalEditor.cpp:935` 在诊断为空时显示“检查通过 · 未发现连接问题”。**由该界面条件与本次 0 诊断用例可推断，这些漏检也可能显示通过。**本次 26 个用例直接调用与界面相同的核心诊断路径，未逐一人工打开窗口截图。
- `src/CircImport.cpp:559` 的 `circDiagnostics()` 只提取持久化导入说明，不是另一套完整 ERC 引擎。

## 已确认可用的检查

- 普通必选输入悬空、仅有输入而没有驱动的网络。
- 不同值的强驱动冲突、显式 Power/Ground 信号源相连。
- 总线位宽不匹配；网表导出也会拒绝位宽错误。
- X/Z/E 运行态诊断及事件预算耗尽/反馈振荡诊断。
- 对象 ID 重复或非法、无效连接端点、接口重名、缺失及递归子电路定义等结构校验。
- 诊断分级、列表展示、双击定位、修复后清除的现有 GUI 路径。

独立审计直接复现了上述部分行为；振荡等其他已有能力由本次重新执行的现有回归确认。

## 补齐顺序建议

1. 增加静态拓扑规则层及明确的引脚电气类型，优先补普通输出短接、必选输入未驱动、自由端/单端网络；引入显式不连接标记和规则分级。
2. 为电源输入/输出、供电域及电源驱动标记建模，补未供电、电源类型冲突和电源地短路规则。
3. 修正 CLR/CLEAR 的豁免条件；增加规则代码、引脚/网络定位以及当前定义/当前实例树/全工程的检查范围说明。
4. 增加标签名称策略、相似性提示及孤立标签检测，保留合法的远端同名连接和跨实例作用域。
5. 在实体元件模式下加入位号、封装、引脚到焊盘映射及多单元元数据，再做完整性校验；现有纯逻辑元件可明确标记为不适用。
