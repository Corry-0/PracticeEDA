# 方案对比与迭代证据

> 本文是答辩的事实底稿。方案对比是基于当前代码的设计复盘；除明确列出证据的部分外，不表示团队曾经完整实现、压测过所有备选方案。角色 A—D 是本次答辩分工，不是提交作者归属。

## 1. 主要设计选择

| 决策问题 | 可比较方案 | 当前采用与原因 | 付出的代价 | 源码或验证入口 |
| --- | --- | --- | --- | --- |
| 界面技术 | 浏览器 Canvas；Qt；wxWidgets | 延续 C++ / wxWidgets 桌面工程，复用原生事件、窗口和构建环境，减少重写范围 | 桌面依赖配置与平台适配；不提供 Web 在线协作 | `CMakeLists.txt`、`App.cpp`、`DigitalEditor.cpp` |
| 核心组织 | GUI 内直接计算；独立核心库 | `logic_core` 与窗口分开，GUI 和测试复用同一模型、校验与仿真 | 需要显式同步 UI 状态，部分结构编辑要重建仿真 | CMake 核心目标与测试链接 |
| 连接表示 | 坐标相交即连接；对象指针；稳定 ID 端点 | `Endpoint{object,pin}` 保存语义连接，几何路径只负责显示；可保存、重映射、撤销 | 导入外部几何连线需要拓扑转换；ID 必须严格检查 | `LogicSupport.h`、`Project::validate` |
| 层级网络 | 每层独立求值；展开后统一编译 | 层级实例加路径前缀，端点并查集合并，底层求值和网表导出共享网络 | 展开占用内存；设置规模限制；尚非增量编译 | `Simulator::Impl::flatten/find/unite` |
| 调度方式 | 每步扫描所有元件；递归求值；事件队列 | 只将受影响用户排入后续批次；支持状态元件、逻辑时间和迹线 | 队列/集合有开销；没有性能基准证明在所有规模都更快 | `queue`、`step`、`settle` |
| 同时事件语义 | 算一个即发布；整批求值后统一发布 | 同一逻辑时间读取旧网络，避免寄存器采样依赖元件遍历顺序 | 需要暂存输出与受影响网络；仍是单线程执行 | `step()` 的两个循环；时序测试 |
| 信号表达 | bool；每位枚举；位掩码 | `value/known/z/error` 支持 1—32 位总线，区分未知、高阻和冲突 | 门运算需逐位遵守语义，不能直接当整数算 | `Signal`、`evaluate`、`resolve` |
| 撤销重做 | 逆操作命令；局部差量；完整快照 | 小规模教学电路使用全工程快照，组件定义与实例能一起恢复 | 大工程拷贝成本高；历史最多 100 项 | `History`、`LogicEditor::change` |
| 保存方式 | 直接覆写；临时文件替换 | 校验后写同目录临时文件，完成写入后替换目标；保持 JSON v1 | 不等于数据库事务或任意断电下绝对安全 | `serialize/deserialize`、`writeAtomic` |
| 自定义组件 | 另起一套插件模型；普通子电路 | 复用 `Circuit`、稳定端口与现有仿真，包中携带依赖 | 导入必须检查依赖递归并重映射 ID | `CustomComponents.cpp` |
| 外部电路 接入 | 完整兼容；任何未知即拒绝；尽力导入无提示；受限映射并诊断 | 当前选择受限映射：可映射部分继续编辑，不能映射的对象留下可持久化说明 | 被降级组件不参与正确的原始语义仿真；用户需修补 | `CircImport.cpp`、`CIRC_IMPORT_CN.md` |
| 外部格式入库 | 独立校验器；直接塞入 GUI；复用原生入口 | 生成普通 Project，最终走 `deserialize(serialize(p))`，保留同一组原生约束 | 一次额外编解码；错误信息可能偏原生模型层 | 导入器结尾与导入单元测试 |
| 网表输出 | 再写一套坐标连接分析；读取已编译网络 | 从仿真器编译拓扑导出，减少“看着接上但网表没接上”的双重逻辑 | 当前 KiCad 输出只是连接信息，不是可制造 PCB 工程 | `Simulator::netlist`、`component_netlist_tests.cpp` |
| 验证方式 | 仅截图；仅核心单测；核心测试 + GUI 冒烟 | 核心验证语义和错误边界，GUI 验证入口、操作与产物 | 冒烟不能覆盖所有人工使用路径；检查数不是覆盖率 | `tests/`、`runSmoke`、CMake CTest |

## 2. 可以诚实讲述的迭代链

### 阶段一：图形与连线原型

仓库历史保留了 2024—2025 年的原型。`f1a488d` 的提交说明是“A*寻路算法构造”；旧树包含 `DrawBoard`、`ElectronicComponent`、`Myapp`、`cMain` 等文件。这可以证明项目有绘图和路径方面的早期探索，不能直接证明当前正交显示路径仍采用 A*。

当前 `LogicSupport.cpp::orthogonal()` 是显示路径处理。答辩时应说：“早期探索过路径构造，当前核心把可见折线路径和电气端点明确分开。”不要说“当前系统依靠 A* 判定电气连通”。

### 阶段二：建立可保存、可验证的数字逻辑模型

当前 `Project/Circuit/Part/Wire`、原生 JSON、`Project::validate()`、History 和核心测试显示，系统已形成独立于窗口的数据与校验层。稳定端点解决移动、重命名和持久化时的身份问题。

此阶段的先后关系属于按能力依赖整理的讲解顺序；不能仅凭当前文件声称它完成于某一天，或声称它必然早于所有仿真代码。

### 阶段三：从组合逻辑走向总线、状态与层级

当前代码包含位掩码信号、并查集网络、事件批次、寄存器、RAM/ROM、层级展开、迹线和诊断。可用半加器、总线寄存器、层级加法器样例解释能力如何扩展。批次发布解决时序结果依赖遍历顺序的问题；具体历史修复时间没有足够 Git 证据，不编造日期。

### 阶段四：工程复用与网表

`docs/TEST_REPORT_CN.md` 中有 2026-09-21 的验证记录，功能范围见 `docs/CUSTOM_COMPONENTS_NETLIST_CN.md`；当前 `CustomComponents.cpp` 和 `component_netlist_tests.cpp` 支持组件依赖导出、ID 重映射、事务导入和连接网表。这里可以明确引用报告日期，但不能把报告日期当成每个函数的提交日期。

### 阶段五：受限 外部电路 2.7 导入

本轮工作扩展 `.circ` 导入：使用 XML 解析器、按库与组件属性映射、根据几何线段恢复显式网络，将不支持项保存为 Text 诊断，再复用原生反序列化校验。提供示例、中文范围说明和 1067 项运行时检查。原生 `PracticeEDA.logic` / version 1 保存模型保持不变。

这一步的核心取舍是：先给出有边界、可解释、能继续编辑的兼容能力；没有声称完整复现 外部电路 所有元件和时序。

## 4. 答辩可使用的措辞

推荐：“我们比较了三种可行设计，当前代码选择……因为本项目的约束是……代价是……验证入口是……”

推荐：“按现有证据，可以把能力演进归纳成五个阶段。其中旧提交和日期文档能确定部分时间点，其余采用依赖关系组织，不虚构开发排期。”

避免：“我们试遍所有框架后发现最快”“性能提升十倍”“完全兼容 外部电路”“这是工业级 EDA”“某成员独立完成某历史提交”。除非另有可复核记录，否则这些都不能由现有材料证明。

## 5. 后续迭代如何形成可验收任务

1. **拓宽兼容范围**：逐种增加元件与属性；每项都带官方格式样例、端口位置与仿真对照，不直接宣布全量兼容。
2. **大规模编辑**：先建立不同规模的加载、编译、历史内存基准，再决定差量历史与增量网络是否值得引入。
3. **更清晰的状态恢复**：若要保存仿真现场，设计独立的状态快照版本，不混入目前的初始值字段。
4. **提升验证强度**：补充随机合法网络、导入语料回归和跨平台 GUI 测试；将覆盖率和性能测试作为未来测量工作。
